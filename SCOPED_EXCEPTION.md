# One-case unconfirmed-application disposition

This is a separately approved risk decision, not evidence class A and not an
unwritten-success recovery. Existing A/B/C evidence remains unchanged. The
disposition is `CLOSED_EXCEPTION_UNCONFIRMED`, with original `next=0`, error,
plan, ticket and snapshot preserved. It revokes broker-local reuse only. A
previously exported native request is not cancelled by this disposition.

Only the exact private case, unchanged full page/properties/revision, original
evidence and original installed backups are eligible. Positive dispatch or
application evidence, target drift, conflicting ownership, changed approved
bytes or missing actual controls reject closure. The supplied approval must
explicitly accept unconfirmed application and the uncancelled exported request,
and bind the exact manifest, source head and original one-literal impact.
Check-only cannot create approval, a lock, a retirement or an audit.

The supported limited impact is one Router scoped-owner literal. A late write
may make the retired manual marker appear again. That marker is not authority:
the same atomic journal commit records the exception terminal, local ticket
revocation, retired owner and new bounded recovery issuer/generation. Neither
the old owner nor a different plan under an approved admission ID can begin a
participating central write. Missing retirement is a blocking corruption.

## Actual execution controls

Install and verify the exact broker, runner, `case_exception.cjs`,
`case_gate.cjs` and `central_case_owner.js` before closure. These dependency
files must travel with the broker, including in later runtime installs.
The current hosted runner must use `central_case_owner.js` for its ownership
callback: it reads canonical authority and the actual central automation run,
and calls the existing fresh prerequisite checks. Missing capabilities fail
closed. Router's old manual text is never an ownership source for this path.

The two existing role wrappers retain permissions, usage/auth gates, native
timers, role locks and ordinary task preflight. Their actual Claude invocation
adds an explicit `--settings` file with a synchronous `PreToolUse` command hook
and a canonical case context. The hook does not return an `allow` permission
decision. It only blocks protected native writes without the exact current
canonical admission; unrelated existing tasks continue under normal policy.
Use the documented `onFailure: block` plus a bounded shell command ending in
`|| exit 2`. Verify that the installed CLI really honors both normal denial
and missing/failing hook denial. Test both current Notion namespaces and
UUID/URL spellings. Unknown mutation targets are rejected. Original ADMISSION
and STATUS files remain immutable audit inputs; the new canonical receipt is
the sole new permission source for that task. No shell sandbox or general
source-write containment is claimed by this incident gate.

The exact central worker-start command is `case_gate.cjs targeted-start` with
the protected original page, role and pinned private gate config. It checks the
canonical receipt before requesting the same existing systemd unit. Generic
timer runs remain scans: without that receipt their protected native CLAIM or
other original-row write is denied by the actual hook. After new canonical
admission, late stale Router text cannot mint or change its issuer/generation.

`record_case_admission` accepts only completed, fully verified owner-bound
batches matching the approved plan hashes and original packet hashes. It does
not fabricate worker proof. `release_case_owner` consumes a fresh native own
CLAIM whose body and properties agree; it records an observation and releases
only the recovery exclusive scope. A request, service start or hook test is not
actual intake. Existing review, Codex, CI, merge and product gates remain.

## One operational approval package

Prepare one exact head, private manifest/config and evidence digests, expected
wrapper/settings/integrity pins, exact admission plans and approval template.
Do not publish private site inputs or grant operational approval while staging.
The previous publication approval for another head is not permission to push
this one. One requested approval may explicitly cover the revised same-PR push,
normal CI/review/landing, exact install and case apply, plus a bounded pause of
the named central scheduler during maintenance and restoration of its exact
enabled/schedule/prompt configuration. Pause does not prove an active run ended:
inspect that run, and refuse installation/apply while an actual competing run
or role is active. Existing role/repair locks serialize installation; do not
remove locks or stop unrelated work.

After approved installation, re-read every pin and actual wrapper settings,
verify source-backed runtime probes, then check-only against fresh originals.
Apply writes the full audit before a single canonical commit. An audit-first
failure leaves the old barrier and resumes from the same validated audit. A
journal failure cannot publish a grant or relax exclusivity only in memory.
Retries validate the exact original fields, approval bytes and preservation
readback; they never clear a newer active batch. Do not roll back to a runtime
which cannot enforce a committed retirement. On a post-closure failure retain
the retirement and owner restriction, preserve the new failure, and do not start
the writer until the pinned admission is actually verified.

Then verify barrier, entire protected content/properties and original worker
proof; recheck current central ownership; perform the approved existing packet
admission; use the guarded existing service; observe the real new writer CLAIM.
Only then release the recovery scope and restore the bounded scheduler pause.
No other provider review budget is changed by this package.
